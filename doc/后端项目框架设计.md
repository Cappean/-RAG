## 3. 异步任务：不需要 Redis

```mermaid
flowchart LR
    API[未来的文档上传 API] --> JOBS[(MongoDB jobs)]
    JOBS --> WORKER[独立 Worker 进程]
    WORKER --> HANDLER[任务处理器]
    HANDLER --> SERVICES[未来的解析 / 切片 / 向量化服务]
    WORKER --> JOBS
```

API 与 Worker 是同一仓库中的不同进程。API 不在请求内等待整个文档入库完成；未来创建任务后返回 202，查询接口读取任务状态。当前尚未实现这些业务 HTTP 接口。

选用 MongoDB 持久化任务，避免进程内队列在 API 重启时丢失。MongoDB 原子的 `find_one_and_update` 用于领取任务，不需要 MongoDB 事务或副本集才能执行这一步。

### jobs 集合字段

这是框架内部任务结构，尚未定义成对外 API；后续业务任务查询可转换为前端约定的字段。

| 字段 | 含义 |
|---|---|
| `_id` | 任务唯一 ID，当前使用 UUID 字符串 |
| `kind` | 处理器名称，当前仅支持 `demo.noop` |
| `payload` | 任务参数，后续优先传 documentId 等引用，避免放整份文件 |
| `status` | `queued` 等待、`running` 执行、`succeeded` 成功、`failed` 失败 |
| `attempts` | 已领取执行次数，每次领取加一 |
| `max_attempts` | 最大执行次数，默认 3 次 |
| `created_at` / `updated_at` | 创建和最近更新的 UTC 时间 |
| `available_at` | 允许下一次领取的时间，用于重试退避 |
| `lease_until` | 本次领取的有效期，默认 60 秒 |
| `lease_token` | 本次执行的唯一令牌，防止旧 Worker 覆盖新执行结果 |
| `error_code` | 失败或等待重试的原因代码，暂不保存异常原文 |
| `result` | 任务结果摘要，后续存资源 ID，避免放大段原文 |

联合索引：`(status, available_at)` 用于领取等待任务；`(status, lease_until)` 用于查找过期任务。`_id` 使用 MongoDB 自带唯一索引。执行 `medical-init-db` 才会创建索引；本次未执行。

### 执行与恢复规则

1. Worker 原子领取可执行任务或租约过期任务，并设置执行令牌。
2. 默认并发 2 个异步槽位，每 15 秒续租一次；配置必须留出足够续租余量。
3. 成功、失败、续租都带执行令牌与有效租约条件，旧执行者不能覆盖新执行者。
4. 普通异常最多执行 3 次，重试等待按 `min(2^attempts, 60)` 秒递增；永久失败不重试。
5. Worker 崩溃后，等待租约过期再领取；最后一次执行崩溃且次数耗尽时标记失败。
6. 续租失败时取消当前异步处理，避免继续提交状态；但已经发生的外部副作用不能自动撤销。
7. Linux 信号触发停止领取，默认等待 10 秒后取消未完成任务；Windows Ctrl+C 按 asyncio 取消路径退出，未确认完成的任务交由租约恢复。

任务保证是“至少执行一次”，业务处理器必须实现幂等。例如使用 documentId + version + chunkIndex 生成确定性 chunk ID，重复写入采用 upsert。数据库领取成功不代表跨 MinIO、Milvus、MongoDB 的整条链路具有事务性；业务补偿后续实现。

当前仓储依赖 Worker 机器的 UTC 时间；多机执行前需保证时钟同步。复杂调度、优先级、取消任务、人工重试接口、进度上报和调度面板尚未实现。

`asyncio` 适合数据库、HTTP、对象存储等等待操作。PDF 解析和模型推理不能直接同步阻塞 Worker 事件循环；后续按任务性质接入线程/独立进程或专用模型进程。当前未实现 CPU/GPU 执行池。

## 4. API 和配置边界

- 已有业务外的探活：`GET /api/health/live`。只证明 API 存活，不证明数据库、模型可用。
- Swagger：启动后访问 `/docs`；当前只列出探活接口。
- 错误响应沿用前端指南的 `error.code/message/details/requestId`，HTTP 状态码仍放在 HTTP 响应中。
- 请求 ID 支持 `X-Request-Id`，只接受 1～80 位字母、数字、下划线、连字符；不合法时重新生成。
- `.env` 不提交；连接串和密钥使用 SecretStr，配置对象展示时隐藏。
- 不配置前端 CORS、不做登录权限、不注册此前文档中的患者/会话/文档路由。
- Milvus、MinIO、DeepSeek、模型目录现在只保存配置，不初始化或检查外部服务。

## 5. 开发日志机制

开发过程统一记录在同目录的 `后端项目开发日志.md`，不把它当成程序运行日志。

每次开发记录：日期与变更编号、需求及边界、关键决策、改动文件、实际验证命令与结果、未验证部分、后续事项。完成状态以证据为准，不把预留目录记为业务功能完成。需求改变时追加记录并指出影响，不覆盖历史结论。

本次不搭建 JSON 日志、日志轮转、审计日志或 MongoDB 日志集合。Uvicorn 默认输出和少量标准库告警保留，运行时日志以后单独设计。
