# 医疗智能问诊前端接口指南

本指南面向 Vue 前端与 FastAPI 后端联调。接口统一使用 `/api` 前缀，JSON 使用 UTF-8，时间使用 ISO 8601 UTC 字符串。示例中的 ID 均为字符串形式的 MongoDB ObjectId；前端不依赖其具体格式。

## 1. 通用约定

### 请求头

```http
Authorization: Bearer <access_token>
Content-Type: application/json
X-Request-Id: optional-client-request-id
```

开发阶段可以暂时关闭鉴权，但接口仍保留 `Authorization` 位置。上传文件使用 `multipart/form-data`，SSE 请求使用 `Accept: text/event-stream`。

### 分页参数

需要分页的 GET 接口支持：

```text
page=1&pageSize=20
```

响应格式：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 0
}
```

### 错误格式

所有非 2xx 响应使用统一结构：

```json
{
  "error": {
    "code": "CONVERSATION_NOT_FOUND",
    "message": "问诊会话不存在",
    "details": {},
    "requestId": "req_01J..."
  }
}
```

常用错误码：

| HTTP | code | 说明 |
|---:|---|---|
| 400 | `INVALID_REQUEST` | 参数格式或业务校验失败 |
| 401 | `UNAUTHORIZED` | 未登录或令牌失效 |
| 403 | `FORBIDDEN` | 无权访问该患者、会话或文档 |
| 404 | `RESOURCE_NOT_FOUND` | 资源不存在 |
| 409 | `DUPLICATE_RESOURCE` | 重复创建或重复上传 |
| 413 | `FILE_TOO_LARGE` | 文件超过大小限制 |
| 415 | `UNSUPPORTED_FILE_TYPE` | 只支持 PDF 或 Markdown |
| 422 | `VALIDATION_ERROR` | 请求字段校验失败 |
| 500 | `INTERNAL_ERROR` | 服务端异常 |
| 503 | `MODEL_UNAVAILABLE` | DeepSeek 或本地模型暂不可用 |

## 2. 患者接口

### 获取患者档案

```http
GET /api/patients/{patientId}
```

响应：

```json
{
  "id": "patient_123",
  "name": "林晨",
  "gender": "男",
  "age": 34,
  "allergies": ["无已知药物过敏"],
  "medicalHistory": [],
  "updatedAt": "2026-10-19T02:24:12Z"
}
```

### 更新患者档案

```http
PUT /api/patients/{patientId}
Content-Type: application/json
```

```json
{
  "name": "林晨",
  "gender": "男",
  "age": 34,
  "allergies": [],
  "medicalHistory": ["既往无消化道手术史"]
}
```

返回更新后的患者对象。患者和会话接口都必须由服务端按当前用户的 `ownerId` 校验权限。

## 3. 会话和消息接口

### 创建问诊会话

```http
POST /api/conversations
```

请求：

```json
{
  "patientId": "patient_123",
  "title": "近期上腹隐痛"
}
```

响应 `201 Created`：

```json
{
  "id": "conversation_123",
  "patientId": "patient_123",
  "title": "近期上腹隐痛",
  "status": "active",
  "createdAt": "2026-10-19T02:24:12Z",
  "updatedAt": "2026-10-19T02:24:12Z"
}
```

### 获取会话列表

```http
GET /api/conversations?page=1&pageSize=20&status=active
```

列表项至少返回 `id`、`patientId`、`title`、`status`、`lastMessage`、`updatedAt`，用于左侧历史会话列表。

### 获取会话详情和消息

```http
GET /api/conversations/{conversationId}
GET /api/conversations/{conversationId}/messages?page=1&pageSize=50
```

消息响应示例：

```json
{
  "items": [
    {
      "id": "message_001",
      "role": "user",
      "content": "我最近3天经常胃部隐痛，空腹时明显。",
      "createdAt": "2026-10-19T02:24:12Z"
    },
    {
      "id": "message_002",
      "role": "assistant",
      "content": "根据目前信息，先需要确认是否存在黑便、呕血等危险信号。",
      "status": "completed",
      "citations": [],
      "createdAt": "2026-10-19T02:24:16Z"
    }
  ],
  "page": 1,
  "pageSize": 50,
  "total": 2
}
```

### 发送消息并流式获取回答

```http
POST /api/conversations/{conversationId}/messages?stream=true
Accept: text/event-stream
Content-Type: application/json（无附件）或 multipart/form-data（含单个附件）
```

请求：

```json
{
  "content": "吃点苏打饼干会缓解，偶尔伴有轻微反酸。",
  "attachments": [],
  "clientMessageId": "client_msg_001"
}
```

当消息附带一份报告文件时，前端改用 `multipart/form-data`，字段为 `content`（文本）和 `file`（文件）；浏览器自动设置 multipart boundary。服务端保存附件并在用户消息中关联附件元数据。第一版前端适配支持单文件；多文件可以后续把 `file` 扩展为重复字段或使用附件上传接口。

`stream=false` 时返回普通 JSON；前端页面建议使用 `stream=true`。服务端先保存用户消息，再以 SSE 返回助手消息。连接结束前必须发送 `done` 或 `error` 事件。

## 4. SSE 事件协议

每个事件遵循标准 SSE 格式，字段之间以换行分隔，事件之间多一个空行：

```text
id: evt_001
event: status
data: {"stage":"retrieving","message":"正在检索指南"}

```

事件类型：

| event | 用途 | 前端处理 |
|---|---|---|
| `message.created` | 创建助手消息占位记录 | 保存 `messageId`，显示生成中 |
| `status` | 返回流程阶段 | 更新状态文字或进度 |
| `token` | 增量回答文本 | 追加到当前助手消息 |
| `citation` | 返回一个来源 | 加入来源列表，可立即点击 |
| `message.completed` | 返回完整消息摘要 | 更新消息状态和最终字段 |
| `done` | 本次流正常结束 | 关闭 loading，释放连接 |
| `error` | 流程失败 | 显示错误并允许重试 |

示例：

```text
id: evt_001
event: message.created
data: {"messageId":"message_002","conversationId":"conversation_123"}

id: evt_002
event: status
data: {"stage":"extracting","message":"正在整理症状信息"}

id: evt_003
event: status
data: {"stage":"retrieving","message":"正在检索指南","candidateCount":24}

id: evt_004
event: token
data: {"text":"根据目前信息，"}

id: evt_005
event: token
data: {"text":"需要先排除以下危险信号。"}

id: evt_006
event: citation
data: {"citation":{"chunkId":"chunk_456","documentId":"doc_123","documentVersion":1,"documentName":"消化性溃疡诊疗指南","locator":{"fileType":"pdf","pageIndex":12,"headingPath":"第二章 > 临床表现与分型"},"quote":"十二指肠球部溃疡典型的腹痛节律为饥饿痛或夜间痛。","relevanceScore":0.984}}

id: evt_007
event: message.completed
data: {"messageId":"message_002","status":"completed","citations":["chunk_456"]}

id: evt_008
event: done
data: {"messageId":"message_002"}

```

网络断开时，前端可使用 `Last-Event-ID` 请求头重连；服务端若支持恢复，应从该事件之后继续发送。若暂不支持恢复，前端应按 `messageId` 重新请求消息详情，避免重复追加文本。

## 5. 引用和来源定位

助手消息中的 `citations` 是来源快照，前端不需要再次解析 Milvus。字段建议如下：

```json
{
  "chunkId": "chunk_456",
  "documentId": "doc_123",
  "documentVersion": 1,
  "documentName": "消化性溃疡诊疗指南（2023）",
  "relevanceScore": 0.984,
  "locator": {
    "fileType": "pdf",
    "pageIndex": 12,
    "printedPageLabel": "第10页",
    "headingPath": "第二章 > 临床表现与分型",
    "anchor": null,
    "textStart": null,
    "textEnd": null
  },
  "quote": "……指南原文……"
}
```

定位字段约定：

| 字段 | PDF | Markdown |
|---|---|---|
| `fileType` | `pdf` | `md` |
| `pageIndex` | PDF 物理页序，从 1 开始 | `null` |
| `printedPageLabel` | 原文印刷页码，可为空 | `null` |
| `headingPath` | 章节路径，可为空 | 标题层级路径 |
| `anchor` | 可为空 | HTML 锚点 ID |
| `textStart/textEnd` | 后续高亮用，可为空 | 后续高亮用，可为空 |

前端点击来源时，使用 `documentId` 和定位字段进入文档阅读器：

```text
/knowledge/documents/doc_123?version=1&type=pdf&page=12&chunkId=chunk_456
/knowledge/documents/doc_789?version=1&type=md&anchor=诊断标准&chunkId=chunk_999
```

第一版只要求 PDF 跳页、Markdown 跳标题。`textStart`、`textEnd` 或 PDF 坐标以后用于精确高亮，不影响当前接口。

### 获取文档临时访问地址

```http
GET /api/knowledge/documents/{documentId}/access-url?version=1
```

响应：

```json
{
  "documentId": "doc_123",
  "version": 1,
  "fileType": "pdf",
  "fileName": "消化性溃疡诊疗指南（2023）.pdf",
  "url": "https://minio.example/...signed-url...",
  "expiresAt": "2026-10-19T02:34:12Z"
}
```

URL 必须是短时有效的签名地址。前端不保存 MinIO 的长期访问密钥，也不直接拼接对象存储路径。

## 6. PDF/Markdown 文档接口

### 上传文档

```http
POST /api/knowledge/documents
Content-Type: multipart/form-data
```

表单字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `file` | File | 是 | `.pdf` 或 `.md` |
| `ownerId` | String | 否 | 私人文档归属；共享文档由服务端置空或使用知识库归属 |
| `version` | Integer | 否 | 不传时由服务端生成 |
| `logicalDocumentId` | String | 否 | 同一指南不同版本使用同一逻辑 ID |

响应 `202 Accepted`：

```json
{
  "document": {
    "id": "doc_123",
    "name": "消化性溃疡诊疗指南（2023）.pdf",
    "fileType": "pdf",
    "version": 1,
    "status": "processing",
    "createdAt": "2026-10-19T02:20:00Z"
  },
  "job": {
    "id": "job_123",
    "status": "queued",
    "progress": 0
  }
}
```

### 查询文档和入库任务

```http
GET /api/knowledge/documents?status=ready&page=1&pageSize=20
GET /api/knowledge/documents/{documentId}
GET /api/knowledge/jobs/{jobId}
```

任务响应：

```json
{
  "id": "job_123",
  "documentId": "doc_123",
  "status": "processing",
  "progress": 68,
  "stage": "embedding",
  "errorMessage": null,
  "updatedAt": "2026-10-19T02:22:00Z"
}
```

文档只有 `status=ready` 时参与检索。失败任务返回 `errorMessage`，前端可提供重试按钮：

```http
POST /api/knowledge/jobs/{jobId}/retry
```

### 删除或停用文档

```http
DELETE /api/knowledge/documents/{documentId}
```

建议服务端先将文档标记为 `disabled` 并停止检索，再异步清理 Milvus 向量和 MinIO 文件。已保存的历史消息仍保留引用快照；若原文件已删除，前端应显示“原文暂不可访问”。

## 7. 前端联调建议

1. 页面初始化调用会话列表、患者档案和当前会话消息接口。
2. 新建问诊先调用创建会话，再切换路由到新会话。
3. 发送消息时立即把用户消息加入本地列表，然后连接 SSE；收到 `token` 事件就追加助手文本。
4. 收到 `citation` 事件就更新来源卡片，收到 `done` 后再以消息详情作为最终状态校准。
5. 来源点击先调用临时访问地址，再打开 PDF 阅读器或 Markdown 阅读页，并使用 `pageIndex`/`anchor` 定位。
6. 文件上传显示 `processing` 状态，轮询任务接口或订阅任务 SSE；只有 `ready` 才在知识库列表中标记可用。
