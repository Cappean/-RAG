## 2. 知识模块已实现的行为

- 上传 PDF、UTF-8 原生 Markdown；按上传原始字节 SHA-256 去重。同字节返回原记录、状态与空 taskId，不伪造新任务。
- 上传入口调用真实单进程内存队列，队列满返回明确错误，并将已持久化的新文档标记 failed。显式重提只接受 failed 文档，并创建新 taskId。
- 原始文件保持不可变，原生 Markdown 解析与阅读共用同一对象。PDF 复用既有 MinerU 工具，保留产物目录内文件相对路径，切分只接受唯一的 `content_list_v2.json`。
- 入库前清理该文档未完成的切片、向量；全部切分、向量化与向量写入成功后才将文档标记 ready。中途失败或协程取消标记 failed，不能报告可检索成功。
- 提供文档列表、详情、ready 来源摘要、人工重提和短时原文地址。原先开发中的无签名 `/documents/{id}/original` HTTP 路由已删除；原文通过 access-url 和签名对象网关获取。
- RAG 的证据接口只返回当下仍为 ready 的文档切片，并按输入切片 ID 顺序返回真实正文、名称、章节与来源定位。

## 3. 切分与定位的实际边界

PDF 使用 MinerU v2 二维页数组的阅读顺序，不按区域坐标重新排序。页序从 1 开始，已验证的 0～1000 坐标归一到 0～1；跨页聚合保留各自区域，不合成大框。疑似 0～1 坐标或零面积区域不猜测转换，只保留可靠页码；非法结构明确报错，不静默遗漏后成功。

真实样本包含 paragraph、title、table、image、chart、page_footnote，以及显式页眉页脚页码和 reference_list。显式参考文献与目录按切分方案排除；其余支持的内容分别处理。只有图片没有文字时不生成空切片，解析资产仍保存。

小节标题优先使用可靠章节编号，未知层级不补造。切分长度使用实际 BGE-M3 tokenizer，标题前缀计入预算；默认目标 500 tokens、上限 800 tokens。超长句继续切短且不丢字符，超长 HTML 表格展开 rowspan 后保留 colspan 关系，分组重复表头。无法保持完整行结构的超大单行明确失败。当前实现不额外引入句子重叠，方案允许的可选重叠尚未启用。

原生 Markdown 保留输入原文行号，围栏代码中的 `#` 不作为小节标题；管道表格保留原始 Markdown 和真实行范围。长段拆分继承原段区域或原始行范围，因此保证的是段落、表格区域或行范围定位，不承诺逐字高亮。

这不证明任何其他解析器、任意坐标系统或旋转页面都已校验。未知产物仍需独立核对，不能凭字段存在就宣称阅读器高亮可靠。

## 4. BGE-M3 计算审查

本地模型目录为 `D:/ai_models/modelscope_cache/models/bge-m3`。只读核对结果：

| 本地证据 | 实现对应行为 |
| --- | --- |
| `1_Pooling/config.json` 为 CLS pooling，mean pooling 关闭 | 使用 `last_hidden_state[:, 0]` |
| `config.json` 的 hidden_size=1024、max_position_embeddings=8194 | 1024 维 dense；配置限制输入长度不超过模型可用预算 |
| `sparse_linear.pt` 以 weights_only 加载，weight 形状 `[1, 1024]`、bias 形状 `[1]`，值均有限 | 真实学习稀疏头 `Linear(1024, 1)` |
| 本地 README 明确 dense、sparse 两种输出 | 不以 BM25 或 dense-only 封装替代 learned sparse |

另外只读对照了 [FlagEmbedding 官方 M3 实现](https://github.com/FlagOpen/FlagEmbedding/blob/master/FlagEmbedding/finetune/embedder/encoder_only/m3/modeling.py)：dense 为 CLS 后归一化，sparse 为 `relu(sparse_linear(hidden))`，同 token 权重取最大值。当前单条编码、没有 padding 的实现与该计算一致。官方只排除 CLS/EOS/PAD/UNK；审查时源码使用 all_special_ids，还会排除字面 `<mask>` token，这属于特殊输入下的细微差异，不能据此把普通文本验证说成所有输入逐值等价。

编码时 tokenizer 使用 `truncation=False`，超上限明确抛错。RAG 查询构造允许对检索查询使用显式 token 预算；这不改变数据库中保存的原始用户消息或全量历史查询。

## 5. 审查发现与复核状态

下列问题均已向主实现者提供具体源码证据；“已修”表示已重新读取工作区源码，不表示正在运行的旧进程已加载新代码。

| 严重度 | 发现 | 复核状态 |
| --- | --- | --- |
| P1 | dense 模型先赋给共享字段，稀疏权重随后加载失败时，下一次调用可能跳过初始化并使用随机稀疏头 | 已修：模型和稀疏头在局部完整加载后一次发布 |
| P2 | 非 ASCII 签名可使 `hmac.compare_digest` 抛 TypeError，错误请求返回 500 | 已直接复现；随后源码已增加 64 位小写十六进制签名格式校验 |
| P2 | 既有 Milvus 集合仅检查字段存在和 dense 维度，不能提前识别错误主键、字段类型或索引 | 已修：核对 VARCHAR 主键、两类向量字段类型、维度及两路 IP 索引，冲突拒绝且不覆盖 |
| P2 | 关闭一个资源失败会跳过后续资源释放 | 已修：每个资源独立尝试关闭，记录异常类型，继续关闭其余资源 |
| P2 | 待执行入库任务在关闭时任务失败，但 documents 仍可能 processing | 已修：Worker 停止后、关闭 MongoDB 前执行遗留 processing 文档失败标记 |

DeepSeek 流还检查正常 finish_reason；输出长度截断和无正常结束标志的 EOF 不作为 completed 假成功。Milvus 实际版本返回主键字段 `chunkId`，当前适配和请求契约测试按命名主键读取，不再假设统一字段 `id`。

签名网关绑定对象键与过期时间，使用进程内随机密钥和 HMAC，API 重启会使旧链接失效；前端需要重新请求 access-url。网关保持 PDF 字节范围响应语义，不过当前先从 MinIO 读完整对象再截取 Range，尚未把 Range 下推到对象存储。默认 20 MiB 上传限制下这是明确的性能限制，多次 Range 会重复读完整对象。
