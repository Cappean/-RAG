# 核心 Demo 启动与验收（2026-10-20）

本记录说明当前实际实现、启动条件和真实验收证据，不改写既有设计中的确认状态。此前《核心Demo实现审查记录》属于阶段审查，其中特殊 token 排除差异现已修正为 CLS/EOS/PAD/UNK；最终目录过滤和真实重入库结果以本记录及所链接报告为准。

## 启动

在 Windows PowerShell 中启动后端：

```powershell
Set-Location 'E:\尚硅谷\实战\后端'
uv sync --locked --dev
.\.venv\Scripts\medical-api.exe
```

不要在 API 正运行时执行 `uv sync`：Windows 会锁定已安装的启动程序。API 只能启动一个进程，不使用多 worker；日常运行不启用 reload，以免丢失内存任务。第二个终端启动前端：

```powershell
Set-Location 'E:\尚硅谷\实战\后端\src\front'
npm ci
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173
```

访问 `http://127.0.0.1:5173`；API 为 `http://127.0.0.1:8000`，OpenAPI 为 `/docs`。Vite 将 `/api` 转发到 8000，签名原文也通过同源网关读取。`GET /api/health/live` 只证明进程存活，不能证明数据库、模型全部可用。

当前已有 `.env`，沿用其中凭据，不复制或输出密钥。支持无前缀和 `MEDICAL_` 前缀配置；同一配置两者同时存在时无前缀优先。当前实测数据库是 `.env` 指定的 `_consultation`，与设计和配置默认值 `medical_consultation` 不同；未擅自迁移或改名，测试数据存于前者。配置默认 worker 并发 1，现有环境指定 2，表示同一 API 内两个消费协程，仍无独立 Worker 进程。

需要运行中的 MongoDB、MinIO、Milvus、本地 BGE-M3 模型，以及有效 DeepSeek 凭据。新 PDF 解析需要 MinerU 凭据；已经保存解析产物的失败 PDF 可以直接复用。实际验证环境为 Python 3.13.13、MongoDB 7.0.34、Milvus 2.5.5；使用锁文件中的 SDK。BGE-M3 路径为 `D:/ai_models/modelscope_cache/models/bge-m3`，使用 CPU 和真实 `sparse_linear.pt`，不加载 Reranker。

## 实际操作

1. 新增或选择患者，按需要编辑性别、出生日期、过敏史、既往史和用药。未知出生日期保持为空，不按年龄伪造日期。
2. 上传 PDF 或 UTF-8 Markdown，等待文档 ready。页面显示内存任务进度；失败可人工重试。相同原始字节返回已有文档，不新建任务。
3. 输入问题，观察流式回答与真实检索证据；继续提问形成多轮会话。刷新后重新读取完整历史。
4. 点击证据打开原文。PDF 使用 PDF.js 实际渲染物理页和多区域高亮；Markdown 显示同一原始文件的行号及范围高亮。没有可靠定位时明确提示，仅打开原文。

无患者咨询、无证据通用模型回退、文档停用/物理删除、历史患者快照语义仍需要业务确认，未将建议自动视为已批准需求。当前要求选择患者，未找到证据时明确失败；不提供文档删除/停用操作。当前历史页面和后续轮次读取最新患者档案，不具备历史档案还原能力。这是现有 ID 关联存储的边界，不是对 P-05 的业务确认。

## 实现与技术默认值

后端按 `patient / consultation / knowledge / rag` 分模块，路由、业务服务和仓储分层；复用现有日志工具和 MinerU 工具。MongoDB 保存患者、会话、消息、文档、切片；MinIO 保存不可变原文和解析产物；Milvus 保存 1024 维 dense 和 learned sparse，双路 IP 检索后 RRF 融合，再从 MongoDB 读取正文及定位。DeepSeek 提供真实增量回答，无 mock 或失败后模拟回退。

普通成功响应直接返回对象或数组；所有业务列表全量返回、不分页。错误包含业务码、公开提示及请求 ID。SSE 事件为 `assistant_created / status / citations / token / done / error`，流开始前的校验仍使用 HTTP 4xx/5xx。

| 技术项 | 当前默认或行为 |
| --- | --- |
| 上传 | 最大 20 MiB；PDF 格式前缀及 UTF-8 Markdown 校验 |
| 切分 | 实际 BGE tokenizer，目标 500、最大 800 tokens，含标题；目前不增加可选句子重叠，80 是预留上限配置，不表示已产生重叠 |
| 检索 | 每路候选为 topK 的 3 倍，融合 topK=6；无医学可信概率解释 |
| 上下文 | 最近 12 条已完成消息；证据总预算 16000 字符；查询最多 1024 tokens |
| 生成 | 最多 1600 输出 tokens，总超时 180 秒；未正常 stop、截断、空回答均失败 |
| 同会话并发 | 拒绝并返回 409；前端禁用重复发送，不自动重发 |
| 断连/超时 | 尽力取消、保留部分回答及证据并标记 failed；每累计 512 字符保存中间文本 |
| 内存队列 | 容量 32、终态记录最多 256、默认关闭等待 10 秒；失败需人工重提 |
| 启动恢复 | 遗留 generating 消息与 processing 文档标记失败，不自动恢复任务 |
| 原文链接 | 默认 900 秒，进程随机 HMAC 密钥；到期或重启后重新打开以取新链接 |

知识入库仅在全部向量写入成功后发布 ready；重试先清理该 documentId 的未完成索引。PDF 已有 `parserOutputPrefix` 时，要求其中唯一 `content_list_v2.json`，直接复用，不重复云解析；缺失或歧义明确失败。目录按显式目录起点和续段特征过滤，不删除整个目录所在页；真实样本排除 5 段目录，第 4 页正文仍保留。

DEBUG 记录阶段和耗时，INFO 记录关键 ID、数量、终态；不打印医疗正文、密钥和完整签名 URL。CLI 关闭 Uvicorn access log，避免查询参数泄漏。

## 剩余限制与待确认事项

- 当前没有鉴权，仅用于本机 Demo；附件、独立搜索、通知、语音和会话删除等后续功能未实现。
- 手册为患者资料，不是经本项目临床审核的正式诊疗指南。检索可以召回封面、版本说明等相关性较弱内容；尚未建立医学检索评测集、召回阈值或结论可信度校准。
- 引用证明来自真实片段、编号属于当前证据，不证明回答每句话都被证据语义支持。没有医学结论自动审定。
- PDF 目录检测对本样本通过，不保证任意未知 OCR；bbox 只验证了本 MinerU 坐标格式及样本，未知旋转/坐标会退为页定位或拒绝。定位是段落/表格区域、MD 行范围，不是逐字高亮。CMap 与标准字体覆盖 PDF.js 资源路径，不能保证任意外部 PDF 的所有字体都完美呈现。
- 原文 Range 目前先完整读取 MinIO 对象再截取，多次请求会重复读取；默认大小限制下可运行，未做大文件优化。
- BGE-M3 首次加载及全 PDF CPU 入库明显耗时；首次解析和入库约十分钟，修复后复用产物重嵌入约六分钟，不是即时完成。
- 单进程任务和签名密钥在重启后失效；持久化文档/消息仍在。无持久任务、自动恢复或自动重试，不支持多进程部署。
- 无患者咨询、无证据回答、文档停用/清理和历史档案是否快照，仍需集中业务确认；现有保守限制不等同于正式批准这些行为。
- 既有工作区文档的修改、删除和移动均按原状保留，本次只新增交付文档，不将用户已有变更归为本次实现。
