# 问诊与上传任务进度效果设计

更新时间：2026-10-20。仅说明期望的页面效果，不展开技术实现。首期不实现问诊附件。

## 1. 问诊过程

- 发送问题后，立即显示用户消息和助手处理提示，避免页面没有反馈。
- 助手回答区域显示阶段条：**整理问诊信息 → 检索指南 → 整理引用 → 生成回答 → 完成**。
- 已完成步骤显示勾选，当前步骤显示活动动画，后续步骤保持待处理；不显示百分比和预计剩余时间。
- 回答逐段出现，同时展示引用来源；点击来源可打开对应文档位置。
- 生成期间可浏览历史、切换会话或进入上传页面；原会话继续生成，切回后可查看最新内容，内容不会串到其他会话。
- 同一会话回答未完成时不能再次发送；仍可编辑补充内容，待完成后发送。

## 2. 知识库上传

- 选择文件后，立即显示文件名、“正在上传并保存文件”和动态活动条。
- 文件接收后，显示任务卡片及阶段条：**等待处理 → 解析文档 → 切分内容 → 生成向量并入库 → 完成**。
- PDF 显示解析步骤；Markdown 跳过不适用步骤。只展示实际执行的过程。
- 阶段条显示已完成、当前和待处理步骤，不显示百分比；耗时较长时保留活动动画和阶段说明。
- 每份文件独立展示进度。切换到问诊页面不影响已接收文件的后台处理，返回后可继续查看进度。
- 完成后显示“入库完成，可用于问诊检索”；重复文件提示“文档已存在”并显示已有状态。

## 3. 失败与交互

- 失败时停止活动动画，标明失败阶段和简明原因，不一直转圈。
- 问诊中断时保留已显示的部分回答并标注“回答未完成”；上传处理失败时提供重新提交按钮。
- 网络暂时异常显示“连接异常，正在重新获取状态”，不直接当作处理失败；状态无法恢复时明确提示。
- 问诊和上传互不锁住整个页面，仅限制重复发送、重复上传等冲突操作。

## 已做出的决定

- 2026-10-20：首期不实现问诊附件；本文范围仅包括文字问诊过程与知识库文件上传/入库任务的进度展示。
- 2026-10-20：问诊使用 SSE 推送真实阶段、引用、回答片段和终止结果；仅收到 `done` 才算正常完成。
- 2026-10-20：知识库入库采用 `taskId` 查询异步任务；任务阶段由后端真实处理步骤更新，文档可检索状态由 `documents.status` 表达。
- 2026-10-20：进度条展示已完成、当前和待处理阶段，不显示百分比或估算剩余时间；批次/切片数只作为实际计数提示。
- 2026-10-20：首期任务状态存于单个 API 进程内存，不引入 Redis、MongoDB `jobs` 集合或独立 Worker；进程重启后任务阶段不可恢复，文档持久化状态仍可读取。
- 2026-10-20：上传进度与后台处理进度是不同阶段；文件传输期间由浏览器本地观测，成功入队后才产生可查询的 `taskId`。
- 2026-10-20：问诊生成、文件上传与后台入库采用互相独立的 UI 状态，不以全局忙碌状态锁住无冲突操作。
- 2026-10-20：本文为目标技术设计，现有阶段回调和 SSE 不等于已经完成阶段条；本次仅生成文档，不实施代码修改。
- 2026-10-20：应用内切换会话或页面保留问诊连接；真实断线保存部分消息并按失败处理，首期不做断流续传或自动重发。
- 2026-10-20：首期无独立重排阶段；文档分批向量生成与写入统一为 `vectorizing`，失败位置通过 `failedStage` 保留，不适用阶段通过 `skippedStages` 表达。
- 2026-10-20：任务关联存入浏览器 `sessionStorage` 以支持同浏览器刷新后恢复查询；文件上传先采用不定量活动条，不额外改用字节进度接口。
- 2026-10-20：进程启动时将遗留处理中但无法恢复的文档标为失败，允许人工重新提交；补充正常、切换、并发、失败与重启场景的验收要点。
- 2026-10-20：按用户要求，正文精简为问诊、上传和异常处理的页面效果，取消详细技术设计；下列既有技术决定仅作历史记录，具体实现方式留待后续设计，不由本效果文档限定。
- 2026-10-20：确认阶段标识为接口契约：问诊 `intake/retrieval/citation/generation/done`，入库 `queued/parse/split/vectorize/done`；中文文案由前端映射，后端不返回展示文案，统一定义在 `后端/src/app/common/stages.py`。
- 2026-10-20：问诊阶段由 `RagService.prepare_steps` 在每一步真正开始前上报，经 SSE `status` 事件推送；`done` 只在消息持久化成功后发送，失败时不发送 `done`，页面据此停止动画并把失败停在当前步骤。
- 2026-10-20：入库任务公开体新增 `stage`、`stageDetail`、`skippedStages`、`failedStage`、`documentId`；Markdown 在任务开始前声明 `parse` 为不适用；`done` 在文档置为 `ready` 后标记；失败时保留 `failedStage`，`error` 只含面向用户的说明。
- 2026-10-20：前端新增阶段条组件，按“已完成 / 当前 / 待处理 / 不适用 / 失败”渲染；阶段内仅显示实际计数（如 `2/2`），不显示百分比与剩余时间。
- 2026-10-20：问诊在途状态按会话保存在前端内存，生成期间允许切换会话与页面；切回时以服务端历史为底、再叠加内存中的最新片段，内容不串会话；输入框保持可编辑，只禁止同会话重复发送。
- 2026-10-20：页内导航改为 `pushState` 前端跳转，避免整页刷新掐断 SSE；浏览器刷新仍按断线处理，首期不做断流续传。
- 2026-10-20：任务关联写入 `sessionStorage` 仅用于刷新后恢复查询；查询返回 404 视为进程重启后的状态不可恢复，页面明确提示并停止轮询；其它网络错误先提示“连接异常，正在重新获取状态”，连续三次失败才停止。
- 2026-10-20：文件传输阶段仍由浏览器本地观测（不定量活动条），与入队后的任务阶段分开呈现；重复文件提示“文档已存在”并展示持久化状态。
- 2026-10-20：本轮为代码实施，含后端阶段上报、前端阶段条与并发/断线处理；PDF 解析阶段沿用既有 MinerU 路径，未引入新依赖，也未新增 Redis 或独立 Worker。
